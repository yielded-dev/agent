# Ordered cold await inventory

Baseline main `b246f8aa`; exact event order and SQL live in `map/ordered-awaits.json`. This extends the linked prod-admit/prod-turn inventories rather than treating each `yield*` as an I/O wait. A yielded service lookup, synchronous SQL cursor, Schema parser, Layer allocation or semaphore permit can complete synchronously. Native transaction promises, KV/alarm methods, crypto digest promises, and transport/stream awaits are listed separately. Warm means a later turn in the same Object incarnation.

`observedAwait` captures START/END for platform operations and KV get in map samples. Storage proxies additionally capture every native transaction callback/return and every KV/alarm dispatch. Crypto promises are source-inventoried here rather than wrapped: extra async boundaries would distort the constructor under study. The trace includes every SQL statement and logical event, so all three inspection transactions, the registration/reconciliation transactions, and first-use read differences are independently countable. Default persisted-value decode checks and Effect's existing AST parser caches remain enabled. Output gates can combine multiple logical transactions into one externally observed stall; no count is labeled a replication round trip.
