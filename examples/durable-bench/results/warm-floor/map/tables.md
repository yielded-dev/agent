- Cloudflare invocation wall time is not caller wall time. Whole-invocation CPU and wall values may extend beyond driver completion; boundary alarms are identified and prevent a turn-attributed CPU total. No sum is a critical-path decomposition.
- Metrics are read after driver completion. Observed alarms, SQL counters, spans, waiterReads and event acquisitions can include follow-up work. A missing alarm end in the receipt is not proof of failure.
- afterAwaitBody counters compare the observer's logical awaitSettlement endpoint return with later metrics collection. That return precedes native gated RPC delivery; these counters cannot establish that work followed client-visible settlement or blocked the next submit.
- waiterReadCount/intervals are optional SQL-read observations on the Object I/O clock. Empty waiterReads does not mean no polling. waiterStatusReadCount, waiterHintCount, waiterFallbackCount and waiterSnapshotDecodeCount are separate semantic counters scoped to the awaitSettlement invocation; these distinguish authoritative reads and wake causes even when a cached read does no SQL.
- Runtime is cached per Object incarnation: a stable incarnation implies zero new runtime initializations between passes. eventAcquisitions counts event-layer acquisition, not runtime construction; runRecovery spans separately describe observed recovery work.
- SSE provider receipts are preferred; a unique matching provider log is an explicit fallback. Fallbacks, missing logs, conflicting logs, telemetry poll metadata, and all non-ok outcomes remain inventoried.
- Legacy paired differences are production minus inline. Candidate comparisons pool the two identical baseline labels (production/repeat) within each Object and subtract the candidate. Positive means a saving. Both raw baseline repeat range and baseline-label median difference are reported; neither is a statistical significance test. No saving below the repeat spread is claimed.
- Across-Object spread uses Object medians; repeatSpread measures first-to-last drift and range within each Object. Stable repeats on a slow Object do not remove that Object from the distribution. Retired Object pairs, if any, remain excluded evidence, including their failures; replacements alone count toward the recorded plan.
