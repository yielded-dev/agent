authenticates requests and routes them to that owner. SQLite retains accepted work
across eviction; alarms bring the Object back to advance it.

## Create the thread object

Install `@yielded/agent-platform-cloudflare@beta`, `effect`, `effect-cf`, and your
provider. Reuse the [example agent and provider setup](https://github.com/yielded-dev/agent/blob/main/docs/snippets/travel-planner/node-agent.ts):

```ts twoslash
// @types: @cloudflare/workers-types
import { definitions, ModelLive, OpenAiLive, planner } from "./node-agent.ts";
// ---cut---
import { ThreadObject } from "@yielded/agent-platform-cloudflare";
import { Layer } from "effect";

const RuntimeLive = ThreadObject.layer([{ agent: planner, model: ModelLive, definitions }]).pipe(
  Layer.provide(OpenAiLive),
);

export class TravelThread extends ThreadObject.make(RuntimeLive, {
  namespaceBinding: "THREADS",
  deploymentId: "travel-planner",
  producerPrefix: "travel-worker",
}) {}
```

Bind the exported class as a SQLite Durable Object under `THREADS`, enable
`nodejs_compat`, and supply the provider secret. The
[runnable travel planner](https://github.com/yielded-dev/agent/tree/main/examples/travel-planner)
includes deployment and application wiring. No separate storage Layer is needed.

## Connect from your Worker

`CloudflareThreadClient.layerFromBinding({ namespace: env.THREADS })` supplies the
client. Submit authenticated input with a Thread ID, principal, idempotency key, and
definition digests. Admission arms maintenance before accepting work and returns a
receipt after durable writes. It enqueues execution; the receipt is not the result.

Use `awaitSettlementRecord(receipt)` for the canonical terminal record and decode
ordinary completed output with the agent's Schema. Use `readPage` and `awaitProgress`
for retained updates. Cancelling observation does not abort accepted work.

<a id="preview-live-text"></a>

`watchText(threadId)` supplies provisional text. Reconcile it against canonical
records; reset or discard drafts as directed by its frames. Canonical completion
permanently retires matching drafts, including after reconnects. Drafts disappear on eviction. Intermediary Workers can forward `watchTextBytes(threadId)`
without decoding or re-encoding NDJSON. At the final consumer, pass the byte stream to
`decodeLiveText(threadId, bytes)` to validate its frames and lifecycle. Both streaming
client methods cancel the remote subscription when their stream scope closes.

## Recovery and limits

`effect-cf` owns the native alarm. `ThreadObject.make` registers manual Thread
maintenance and composes application registrations from `options.alarms`. Do not
write the raw alarm slot or replace its handler.

`dispatchAfterEvent` defaults to **true**, starting due work sooner but potentially delaying
cold receipts. To opt out, provide `DurableObjectAlarm.ScheduleConfiguration` with
`{ dispatchAfterEvent: false }` through `Layer.provideMerge` on the application Layer.
In that mode, alarms still start work promptly; the recovery window does not delay execution.

`recoveryWindowMillis` controls recovery after interruption without another client request.
After activity, the Object retains one wake for this window and reuses it for nearby requests.
An empty wake clears itself. A longer window can avoid an alarm write before the first model
request, in exchange for slower recovery without a client. Reopening an Object with pending
work still schedules prompt recovery. Set the window to `0` to restore the short recovery
deadlines and immediate idle cancellation.

| Setting                                  | Default                     |
| ---------------------------------------- | --------------------------- |
| Admission queue depth per Thread         | 256 nonterminal Submissions |
| Encoded input limit                      | 1,900,000 bytes             |
| Database admission ceiling               | 9,000,000,000 bytes         |
| Failed/no-progress pass backoff          | 100 ms base, 5 seconds cap  |
| Recovery window (`recoveryWindowMillis`) | 60,000 ms (60 seconds)      |

An alarm has a ten-minute cooperative yield boundary and fourteen-minute watchdog.
These are event limits; agent `maxDuration` applies to each active durable Attempt
using the Run's original allowance. Suspension is outside that duration. An explicit
Unknown outcome stays unresolved; a restart does not authorize replay.

## Configure runtime services

Provide model, tool, and context Layers before constructing the Object. They are
acquired per incarnation. Keep initialization local and bounded; eviction does not
guarantee finalizers. Use scoped operations or `eventLayer` for timely cleanup.
Keep RPC private and configure `operationAuthorizer`; its default trusts service possession.

<a id="agent-tracing"></a>

Acquire `CloudflareTracer.layer` in `eventLayer` for invocation-specific tracing.

## Share an application Object

Use `ThreadObject.layerInHost` to place logical Threads in an existing Object.
Share its SQL client and mutation gate; keep placement stable. Register
`ThreadObject.alarms` with the host's `DurableObjectAlarm.mergeAll` and call
`ThreadMaintenance.ensureAlarm` during local initialization. Follow the
[shared-owner example](https://github.com/yielded-dev/agent/blob/main/packages/platform-cloudflare/examples/shared-owner.ts).

## Shared memory

`MemoryObject.make` and `CloudflareMemoryClient` provide separately owned documents
shared across Threads. You choose namespaces and authorize access. See the
[memory example](https://github.com/yielded-dev/agent/blob/main/packages/platform-cloudflare/examples/memory.ts)
and [context guide](/guide/context-management/).

## AI Gateway

The Node-safe `/cloudflare-ai-gateway` subpath configures upstream provider clients;
model behavior stays with Effect AI. [Browser](/guide/browser/) and
[Code Mode](/guide/code-mode/) adapters are independent capabilities.
